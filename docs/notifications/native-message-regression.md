# 消息页回归

这是当前检查范围，不是验收通过记录。以源码、接口响应及重载后的页面结果分别确认。

## 页面与交互

- Reply / At / Love / System：独立首屏、分页、刷新、滚动锚点和已读状态；通知卡片使用响应式瀑布流。
- Whisper：分类、搜索、筛选和会话列表保持同一持久侧栏。普通用户与 transient recipient 支持文本、图片和表情；不支持发送的会话显示禁用状态。
- 未选择会话时显示当前账号的 Insights 和全部标为已读入口；原版私信仅作为显式 fallback，不预加载 iframe。
- 用户搜索包括已载入会话、关注用户与全站用户；消息搜索覆盖可读取会话，支持暂停、继续、定位及跨会话匹配导航。
- 会话管理检查置顶、免打扰、内容推送、黑名单和举报；服务端已接受但回读未确认时保留待确认状态。
- 服务端消息设置只位于全局“Bewly 页面 → 消息页”，按字段提交、回读，不存入本地外观设置。

## 数据与生命周期

- 账号或页面切换后旧响应不能落入新视图；隐藏分类释放 DOM、观察器和可见性监听。
- 会话详情遵守页面级 LRU 与消息上限，历史分页使用独立 `historyBoundarySeqno`；当前会话和 ACK 在途请求不会提前淘汰。
- ACK 只在会话可见且位于最新消息区域时提交，成功后通过 `topBarStore` 同步未读。搜索不触发 ACK。
- 只有用户明确提交文本或图片后才允许出现 `web_im/send_msg`；选图和粘贴不能上传。发送接受后以历史对账确认，未确认时不自动重发。
- 上传失败可重试，发送重试复用已上传资源。换会话、换号或卸载取消未发出的步骤并释放对象 URL。
- System 沿用 `unified + user` 首屏、单一 legacy cursor 和 `update_cursor`；详见[协议证据](system-protocol-investigation.md)。

## 验证

自动检查：`pnpm verify:private-message`、`pnpm verify:notifications`、`pnpm verify:selected-p2`。

Chrome 实际检查首屏、分页、搜索与定位、回顶、会话切换、发送和管理操作、设置回读及失败重试。界面覆盖亮色、深色、OLED、关闭毛玻璃、底部/右侧 Dock、窄窗口及 reduced-motion；四种语言不显示原始键名。

记录浏览器、扩展版本和实际操作结果。未执行的服务端写入或浏览器路径标记为未验证，不以编译或历史记录代替。
