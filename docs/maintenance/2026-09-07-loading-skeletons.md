# 加载骨架与播放栏初始化

本轮在 `message_feature` 上继续，保留之前未提交的实色表面调整。未提交、推送或执行生产构建。用户明确保留 Bilibili 原生播放器的媒体缓冲提示；LIVE 状态图标及既有顶部模糊不变。

## 根因与实现

- 页面、弹窗、按钮和 iframe 曾分别使用旋转图标、GIF、纯文字及不同骨架动画。现在由 `SkeletonBlock.vue` 和 `styles/skeleton.scss` 统一绘制；原生 DOM 注入复用相同的 `[data-bew-skeleton]` 样式。
- 部分骨架没有沿用真实内容的布局设置、字体行高和尺寸来源。视频网格继续走实际 `VideoCard` 的 skeleton 分支；删除无调用方的独立 `VideoCardSkeleton.vue`。校准更多按钮、作者、元信息、历史时间列、番剧边框内的封面比例、图文间距、稍后再看标题/作者分组及动态侧栏。
- `applyNow()` 原先在排入原生 resize 后直接移除加载层。现在沿用现有 resize RAF、Observer 和控件显隐策略，等待原生底栏 flex 布局、弹幕宿主和 Shadow DOM 辅助按钮具有有效尺寸，并经过既有 160ms 稳定窗口后退出骨架。`playing` 不能越过布局门槛。辅助按钮预留宽度改为实际宽度加既有间距。
- 图片入口复用 `LazyPicture` 的加载队列、失败回退和释放逻辑；支持调用方的真实宽高比。加载完成、失败或离屏时不继续显示动画。番剧、动态详情的已完成骨架卸载。
- Opus 详情的延迟隐藏按当前节点归属执行，重开取消旧淡出；关闭时释放加载节点、样式、Observer 和三次延迟布局重试。

## 自动验证

`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm knip` 均通过（退出码 0）。Knip 仍报告既有 52 个未使用导出、6 个未使用类型和 4 个枚举成员，不表述为无警告。

`verify-loading-skeletons.mjs` 调用实际模块或编译后的组件，覆盖：

- 媒体 playing 不能提前移除正在进入的播放页骨架；按当前容器测量覆盖层，退出清理 listener/timer/RAF。
- 原生 CSS 未就绪、辅助按钮尚未挂载或仍为纵向时不揭开；尺寸变化重新计稳定时间，稳定后停止 RAF；普通 Dock 模式不等待辅助按钮；切页和清理失效迟到回调。
- Select 保留服务端已知值、加载时禁用操作、完成后卸载占位且不发出写请求。
- 历史时间列和操作按钮数量；搜索前后请求、失焦与卸载时的加载状态归属。
- Opus 初始化、淡出期间重开及最终卸载，验证无重复样式或残留计时器。

既有图片测试通过实际 `Picture → LazyPicture` 入口验证宽高比、原图回退、旧事件失效及完成/失败后停止骨架。原有账号隔离、评论、播放器、私信和通知协议断言保留。JSDOM 时序/尺寸夹具不等同于浏览器视觉验收。

开发阶段使用 `pnpm dev`。删除旧组件后，长期 watch 曾缓存失效的 glob 依赖；已停止根目录旧进程并重新启动完整开发编译，其他工作树进程未改动。新内容脚本实际包含 `bew-history-time-slot`、`controlsLayoutReady` 和共享骨架样式，未手工编辑生成产物。
