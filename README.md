# Bewly_Nocturne

Bewly_Nocturne 是一个面向个人使用习惯定制的 Bilibili 浏览器扩展。它仍是浏览器扩展，不是 macOS、桌面或移动客户端。

## 来源与维护

Bewly_Nocturne 基于 [BewlyCat](https://github.com/keleus/BewlyCat) 开发；BewlyCat 基于 [BewlyBewly](https://github.com/BewlyBewly/BewlyBewly)。本仓库保留原项目历史和贡献者信息。

本项目会继续选择性合并 BewlyCat 上游更新。无冲突的更新正常接收；与 Bewly_Nocturne 定制行为冲突时，经人工审查后保留本地定制。

维护者的分支、Fork、cherry-pick 与上游同步流程见[上游协作流程](docs/maintenance/upstream-workflow.md)。

本项目仅接受外观和视觉交互的issue，底层功能请向上游提交。

本项目假设用户有超过平均线的运行设备，故任何性能和外观之间的取舍都会偏向于外观。

## 夜曲设计一览

Bewly_Nocturne 并不是 BewlyCat 的纯镜像。它在保留 Bilibili 内容能力的基础上，维护一套独立的夜曲视觉与交互设计：
### 添加了

- **独立项目与上游协作体系**：建立 Bewly_Nocturne 的独立品牌、仓库说明、维护文档和双仓库协作流程；官方 BewlyCat 仅作为只读上游，夜曲定制只进入 Bewly_Nocturne。
- **全局页面模式**：加入“全 Bewly / 全原版 / 自定义”三档模式及持久化状态；Dock、页面入口和设置内容保持同步。
- **统一顶栏模式配置**：将顶栏类型作为特殊配置项集成到“Dock 内容调整”，而不是作为 Dock 导航项；全原版模式使用 Bilibili 原生顶栏。
- **Dock 收起模式**：加入按钮收起、隐藏收起入口、离开后自动收起三档行为；收起后形成位于原 Dock 几何中心的毛玻璃圆球。
- **连续 Dock 形变动画**：同一持久毛玻璃外壳在完整胶囊和圆球之间改变真实宽高；外壳先完成伸缩，再加载或退出按钮组，不使用两个 Dock 交叉淡入。
- **感知深色网页背景**：从深色基准色在 OKLCH 色彩空间中约束明度和色度，生成稳定的语义页面背景，同时保留轻微色相倾向。
- **OLED 纯黑模式**：仅在实际深色主题下将网页底层设为 `#000`；卡片、面板、输入框和弹窗继续保留原有表面层级。
- **主题色前景自适应**：增加 `--bew-on-theme-color`，根据最终主题色亮度自动选择黑色或白色前景，使白色、近白色和深色主题均保持可读。
- **连续平滑圆角体系**：加入集中管理的 `corner-shape`、语义圆角和表面边框 Token；不支持 `corner-shape` 的浏览器继续使用原有 `border-radius`。
- **明确的形状语义**：区分真实圆形、完整胶囊和平滑圆角矩形；头像、圆形按钮、Switch、Dock 等不会被普通 Squircle 规则误改。
- **共享基础组件**：加入统一的 `IconButton`、`CloseButton`、`TagRemoveButton`、`PanelTopBlur`、`PageModeSwitcherButton` 等组件，分别处理圆形操作、关闭浮层、删除标签、顶部渐变模糊和页面模式切换。
- **设置页启动动画**：设置窗口从实际 Dock 设置按钮的位置展开和收回，并保留 KeepAlive、滚动位置及内部状态。
- **设置页顶部渐变模糊层**：设置窗口和 Dialog 复用独立装饰层，使渐变模糊在物理边界前自然衰减，不模糊清晰边框和圆角。
- **设置二级导航**：重新组织通用、Bewly 页面、Bilibili 功能、外观和维护设置；为播放页与消息页增加独立空框架，供后续功能扩展。
- **内存节省设置组**：将释放离屏图片、媒体资源等内存相关设置集中到“通用 → 内存节省”，保留各自独立开关和原有存储 Key。
- **共享 URL 净化逻辑**：当前页面链接和分享链接复用同一套 Bilibili 参数分类规则，明确区分追踪参数与导航、播放参数。
- **播放进度归一化**：History、Watch Later 和顶栏弹窗共用有限的 `0–100%` 进度计算，完整播放状态稳定显示为 100%。
- **响应式 URL 状态**：需要感知 SPA 导航的 TopBar、链接和页面状态接入现有 URL 变化机制，避免长期缓存旧地址。
- **扩展重载提示与消息收敛**：增加内容脚本刷新提示、共享状态消息代理和失效上下文识别，扩展更新后旧页面会停止无效轮询并提示刷新。
- **局部请求 generation**：History、搜索建议、视频预览、Ranking、Weekly、Trending 等异步数据源加入轻量请求代次，旧响应不能覆盖当前选择。
- **账号隔离缓存**：首页推荐、动态和关注流按 Bilibili 账号分开保存，切换账号或退出后不再显示上一账号的内容。
- **设置云同步状态**：可查看未同步字段数、容量受限数量和最近一次同步错误。

### 修改了

- **Dock 视觉**：主 Dock 保持 iOS 风格完整胶囊；未选中项不显示圆形底板，Hover 保留发光反馈。浅色模式使用主题色选中背景和主题色光晕，深色模式使用白色发光指示和黑色选中图标。
- **Dock 定位与动画**：修正刷新后的严格居中、不同页面切换时的重复挂载、边框与填充不同步、收起后额外胶囊残影和展开掉帧问题。
- **顶栏视觉**：保留 iOS 风格渐进模糊，并将主题色渐变统一交由外观设置控制；普通实色、毛玻璃和关闭毛玻璃状态使用明确的表面逻辑。
- **毛玻璃设置逻辑**：毛玻璃默认开启；唯一的负向设置会同时关闭全局毛玻璃和普通顶栏渐变，并切换到完整实色版本。
- **设置页表面**：设置窗口、左侧导航 Dock、Dialog、Popover、搜索框和内部控件统一使用夜曲语义表面、边框、圆角和模糊强度。
- **设置页左侧 Dock**：折叠时保持几何胶囊，展开时成为与设置窗口协调的大圆角矩形；展开与折叠使用相同的玻璃透明度和模糊层级。
- **提示卡片和操作按钮**：新版本说明与页面重载提示统一轮廓；登录入口和共享关闭按钮改为更实色的语义表面，提高深浅主题下的可读性。
- **液态分段控件**：现有滑动高亮底板、拉伸、Morph、ResizeObserver 和 reduced-motion 行为固定启用，不再因设置状态退回静态选中效果。
- **媒体轮廓**：视频封面外层成为唯一几何裁切边界；图片、视频预览、Skeleton、遮罩和底部信息渐变继承相同轮廓，Hover Preview 前后不再跳角、露底或产生双边框。
- **卡片与浮层层级**：视频卡片、动态卡片、面板、Dialog、Drawer、Popover、Context Menu、输入控件和骨架屏按语义尺寸保留不同圆角，只统一曲率类型和表面边界。
- **原版 Bilibili 页面适配**：插件 UI 继续通过 Shadow DOM 隔离；原版页面不再被插件页面背景、布局尺寸或透明表面规则覆盖。
- **Shadow DOM 加载失败行为**：主样式未就绪前保持插件容器隐藏；样式加载失败时卸载该次 UI，不再暴露透明、错位的 Dock、Sidebar 或设置窗口。
- **Iframe 主题同步**：有效深色状态、OLED 状态和深色基准色同步到 IframePage、IframeDrawer、通知抽屉等相关 iframe。
- **顶栏动态分页**：最后一页会先处理并追加当前响应数据，再设置结束状态；首次加载、offset、联合投稿和新动态数量保持一致。
- **稍后再看状态**：改用显式页码和请求代次，不再根据数组长度推算下一页；顶栏列表、数量和 VideoCard 完整集合会同步刷新并按 aid 去重。
- **稍后再看跨标签同步**：顶栏、视频卡片、动态和原站增强统一以 `aid` 识别成员，一个标签页修改后会通知其他标签刷新。
- **History 加载**：补屏改为单一异步请求链；空结果、请求失败、相同 cursor、搜索切换和页面状态变化都会正确停止。
- **History 搜索**：刷新时保留当前搜索模式；只有清空关键词才恢复普通历史，旧搜索响应不会覆盖新关键词结果。
- **稳定标识删除**：History 使用业务类型与 oid，Watch Later 使用 aid；异步删除完成后重新定位目标，不再依赖请求前保存的旧 index。
- **Anime 与订阅流分页**：最后一页数据即使 `has_next=false` 仍会被追加；空 `items/sub_items` 不再触发数组访问异常。
- **登录提示复位**：关注、直播和订阅合集页面在重新请求时恢复登录状态，仅在接口再次返回未登录时显示提示。
- **首页榜单竞态**：Ranking、Weekly 和 Trending 快速切换或刷新时只接受当前请求；Trending 失败后不再错误推进页码，并按稳定视频 ID 去重。
- **VideoCard 稍后再看**：优先使用明确 aid，通过 bvid 或 PGC episode 解析缺失 ID；直播卡片不提供稍后再看，失败请求不会产生未处理 Promise。
- **视频 Hover Preview**：卡片视频、Hover 状态或预览设置变化后，旧的直播、cid 和预览 URL 响应不能写入新卡片。
- **稍后再看按钮 Prop**：统一修正 `showWatchLater` 等命名错配，显式关闭按钮时能够真实生效。
- **Filter 规则**：标题和用户过滤规则修改后立即重新编译；单条非法正则会被忽略，未来时间戳不会错误通过发布日期过滤。
- **搜索建议**：旧关键词请求不能覆盖新关键词；新结果会完整替换旧数组，不再残留旧结果尾部，并补齐请求失败处理。
- **搜索 URL 与历史**：非法页码和筛选值会回退默认值；浏览器前进/后退恢复条件时不再重复新增历史记录。
- **筛选编辑器**：新增与编辑分别处理自身输入值，统一 trim、空值和重复判断；Escape 只在实际编辑状态下取消当前操作。
- **Compact UserCard**：点击关注按钮不再同时触发外层用户链接导航。
- **B 币提醒**：关闭提醒后会真正作用于 `vip_rewards` 入口，不再残留红点。
- **通知抽屉生命周期**：合并重复 `handleOpen()`，统一定时任务和全局监听器的创建与清理，反复打开关闭不会累积。
- **播放器计时器**：Clock interval 在 DOM 消失后会真实执行 `clearInterval()`；自动播放开关 selector 不再误命中 Bewly 的随机播放 Switch。
- **分享链接净化**：继续清理追踪参数，但保留 `p`、`t` 等具有分 P、时间定位意义的业务参数；空 query 不留下多余 `?`，hash 保持不变。
- **Favorites URL**：在实际导航时读取当前账号 Cookie，账号切换后不再使用旧 UID，未登录时也不会生成包含 `undefined` 的 URL。
- **设置导入**：按当前 Settings 结构限制允许字段并进行基础类型、枚举和 own-property 校验，拒绝原型污染字段。
- **后台 API 风控解析**：读取 JSON 前保留可复用的 Response，使 HTML 风控页能够进入既有 `ApiRiskControlError` 分支。
- **Firefox 容器账号**：Multi-Account Containers 中的 Cookie 按请求域名、路径、HTTPS 和有效期正确筛选，不再串用其他容器的会话。
- **iframe 与 PIP 稳定性**：修正了非当前 iframe 消息被误处理、PIP 关闭流程和页面通信串请求的问题。
- **站内导航与功能生命周期**：页面模式、深色模式和顶栏在 SPA 导航后及时更新；截图、画面比例和触屏手势仅在对应功能开启时运行。
- **顶栏挂载**：修复未登录或顶栏元素尚未挂载时引用被错误解包、导致 Bilibili 页面报错的问题。
- **顶栏搜索框**：移除页面重新加载时由异步宽度校正触发的横向入场动画，保留即时居中。
- **上游功能同步**：选择性整合动态、评论、播放器、推荐风控、专栏预览和 TopBar 链接等上游修复，并保留夜曲现有架构与视觉。
- **开发内容脚本**：开发模式保留可读函数名，避免长时间 watch 后增量构建出现函数重命名和调用点错配；生产压缩策略不变。
- **Knip 配置**：收紧过宽的 entry 和 ignore，使真实死代码能够重新被识别。

### 去除了

- **完整背景图片功能**：删除壁纸选择、上传、URL 壁纸、缓存、遮罩、模糊、搜索页独立壁纸、存储字段、渲染组件及相关工具。
- **旧顶栏悬浮切换器**：删除搜索框下方的 `BewlyOrBiliTopBarSwitcher.vue`、Teleport、显隐逻辑、层级样式、设置项和废弃文案。
- **旧页面悬浮切换入口**：删除重复的 `BewlyOrBiliPageSwitcher.vue`；页面模式统一通过现有全局状态和 Dock 入口控制。
- **分散的顶栏视觉开关**：删除 `alwaysUseTransparentTopBar`、`enableTopBarGradient`、`showTopBarThemeColorGradient` 等重复状态。
- **旧正向毛玻璃设置**：删除 `enableFrostedGlass`，改为唯一的 `disableFrostedGlass` 负向设置，不保留兼容别名。
- **“使用原版 Bilibili 首页”设置**：删除 `useOriginalBilibiliHomepage` 的 UI、存储字段、监听器和旧数据残留；原版页面仍可通过全局页面模式和 Dock 页面配置进入。
- **兼容性页中的重复顶栏设置**：顶栏显示与类型不再在兼容性页面单独维护，统一归入当前页面模式和 Dock 内容配置。
- **液态分段指示器开关**：删除可见设置项、设置搜索入口和性能警告文案；液态效果本身保留并固定启用。
- **Bewly 全局快捷键**：删除扩展自己的播放器/页面级按键监听及设置入口；Bilibili 原站快捷键和 Dialog、Drawer、图片查看器等局部键盘操作保持不变。
- **冗余设置页面包装层**：删除旧 Advanced、Navigation、Playback 和 PluginComponentsAndPages 聚合页面，改由当前分类与二级导航直接组织叶子模块。
- **重复的顶栏组件设置页**：删除旧 TopBarComponents、TopBarPinnedChannels 等重复 source of truth，保留实际仍在使用的顶栏配置入口。
- **旧 Popup 与 Options 页面**：删除未被 Manifest 暴露、生产构建不使用的 popup/options 源码、HTML 入口、Vite input 和 Manifest 注释残留。
- **失效的 Web 构建任务**：删除已无 HTML 入口依赖的 `build:web` / `dev:web`；开发命令只启动仍有效的扩展编译任务。
- **废弃通知实现**：删除 `notify.ts` 中无调用的注释代码和旧实现。
- **独立 `gridColumns` 存储**：删除重复的旧存储源和迁移回调，当前网格列数只保留一个权威设置来源。
- **无读取方状态与旧消息管线**：清理已确认不可达的 callback、sendResponse、旧状态变量和被现有实现取代的残留。
- **过时设置字段的兼容层**：删除已废弃字段时直接清理，不保留 migration、fallback 或长期兼容别名。
- **Bilibili Evolved 兼容**：删除第三方顶栏的专用样式、DOM 探测、运行时干预、设置和文案；Nocturne 仅维护 Bewly 与 Bilibili 原生顶栏。

## 本地构建

```sh
pnpm install
pnpm dev
```

开发模式不会压缩内容脚本，以保证长时间监听编译时的函数引用稳定；生产构建仍沿用正常压缩流程。重新编译或重载未打包扩展后，已有 Bilibili 页面需要刷新一次以接入新的扩展上下文。

Chrome 生产版及 ZIP：

```sh
pnpm build
pnpm pack:zip
```

构建目录为 `extension/`，压缩包为 `extension.zip`。
