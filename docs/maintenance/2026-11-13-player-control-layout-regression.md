# 控制栏图标与布局回归修复

## 原因

上一轮的 `.bpx-player-ctrl-btn-icon { display: flex }` 覆盖了原生画中画、宽屏等按钮内部进入/退出图标的显隐规则，使两套图标同时显示。与此同时，SVG 高度被设为按钮高度的 100%，原生图标被放大，而听视频等图标仍使用独立的图标尺寸，造成大小、粗细观感不一致。

原有自动夹具将按钮简化成单个 SVG，没有覆盖原生双状态图标结构；此前的通过结果不足以证明这条边界正确。

## 修改

- 不再覆盖原生图标盒的 `display`。图形在盒内居中，进入/退出显隐和原生动画继续由播放器管理。
- 功能图标画布统一使用 `--bew-icon-size-md`，按钮使用 `--bew-control-height`，相邻按钮使用 `--bew-space-2`。Hi-Res、杜比等横向音质标志保留比例。
- 截图和音画调整按钮复用现有 Tabler 图标及 1.75 描边定制，删除单独的 88 单位 SVG。按钮插入位置和处理函数未变。
- 文字按钮不被 flex 压缩，清晰度、倍速、字幕的最小宽度保持一致；时间文本参与实际宽度计算，长时长和大字号不再依赖原生固定宽度。
- 足够宽时保持原顺序单排。原有共享适配器继续负责扩展按钮的窄栏替代入口；即使原生按钮仍放不下，按钮组也可按原顺序换行。进度条固定在按钮组上方，既有共享几何测量负责玻璃卡片高度，无新 Observer 或轮询。

## 验证

- 已有播放控件回归加入原生进入/退出图标互斥检查；该项及截图生命周期、共享空间适配两项回归通过。
- 独立 Chromium 夹具载入生产样式、原生 CSS、实际 `playerControlFit`，仅控制其帧调度与生命周期入口。24 组宽度/界面缩放/normal、web、full 模式，加 4 组大字号和小时级时长：290 项自动断言通过。覆盖顺序、相邻按钮间距、图标画布、垂直中心、前景色、无重叠、边界内布局、状态图标显隐及掩码产物存在。
- `pnpm typecheck`、修改文件 ESLint、`pnpm verify:ui-icons`、样式失效检查与 `git diff --check` 通过。样式检查使用 `node --import tsx` 执行同一脚本，避开沙箱不允许的 CLI IPC 管道。
- 已确认当前开发入口引用最终布局，CSS 中包含新增图标及统一描边。没有运行生产 build、全套测试或实站视觉验收。

页面复核：重新加载扩展并刷新视频页，检查上一首/播放/下一首、音质、听视频、调整、清晰度、倍速、字幕、音量、截图、设置、画中画和项目全屏入口的顺序；切换画中画、听视频和窗口宽度，确认没有第二套图标露出、按钮重叠或无法恢复的隐藏。

## 间距后续修复

用户随后确认尺寸一致，但清晰度到倍速等位置仍有异常留白。原生 `.bpx-player-ctrl-eplist` 正好位于两者之间，普通模式用 `visibility:hidden; width:0` 隐藏；通用图标按钮宽度规则却将它撑为 36px，形成一个不可见按钮和额外的 flex gap。此前夹具遗漏了这个原生占位节点。

- 普通网页模式下隐藏的选集入口退出 flex 布局；全屏、网页全屏及原生 PC 应用普通模式的入口仍保留。
- 清晰度、倍速、字幕和选集文字两侧使用与居中图标一致的内距，即 `(控件高度 − 图标尺寸) / 2`，随界面缩放变化。按钮间 gap 和内容两侧内距共同决定可见间距，不能只验证容器 gap。
- 选集菜单复用其他菜单的垂直定位与悬停连接区，保持可进入。
- 原生显隐回归补齐上述选集模式；隔离 Chromium 夹具增加真实选集占位和文字/图标内容边界测量，314 项断言通过。同一默认尺寸夹具中，模拟旧规则的清晰度到倍速文字间距为 57px，修复后为 24px，与相邻图标画布间隔相同。该数字来自自动夹具，不是用户实站 DOM 测量。
- 修改文件 lint、样式失效检查和差异检查通过；已核对当前开发入口包含最终规则。未运行生产 build 或实站视觉验收。
