# 动态转发输入框与评论统一

## 范围

动态卡片的转发模块采用与常驻评论框相同的输入设计。保留原转发入口、卡片展开机制、转发协议与事务控制，不改页头、侧栏或其他页面布局。

## 实现

- `MomentForwardComposer.vue` 复用 `composer.scss` 的 surface / input：32px 语义圆角、单层磨砂及实色降级，textarea 无独立底板和描边；内容增长到四行后内部滚动。
- 底部使用表情、@ 和话题图标，右侧复用 `.bew-send-button` 的圆形上箭头及 pending 状态。空文案仍允许直接转发，不能借用评论的空输入禁用逻辑。
- 原有表情、用户与话题选择器 Teleport 到应用容器，通过共享 `useComposerPicker` 定位，不增加转发区域高度、不受卡片裁切。空间不足时向上打开，限制可用高度与视口边距；外部点击、Escape、卡片收起、换号和卸载沿用现有清理链路。
- 评论输入框也使用同一定位 helper 与 picker mixin，避免维护两套监听与弹层几何。没有新增轮询、逐帧布局动画或玻璃内部的背景采样。
- 显式 @ 按钮在普通文字 / 表情旁插入必要的分隔空格，保留光标位置与选区替换；选择完成后返回 textarea。原有提及解析边界不变，提交仍使用选中用户的真实 MID。
- 原 `useMomentForwardComposer` / 转发事务继续负责账号、CSRF、请求归属、重复提交与失败草稿；此次不改服务端 API。
- 删除转发独有且不再使用的 textarea 最小 / 最大高度 token。

## 验证

- 536 项 `verify-selected-p2` 回归全部通过，包含转发事务、编辑器保留、评论编辑器与话题 / @ 焦点；TypeScript、相关 ESLint 与 `git diff --check` 通过。
- 本地预览使用真实组件、样式、事务与定位函数，接口替换为 fixture。验证了空文案转发、表情插入、表情后 @、候选选择、话题选择、Escape 回到编辑器，以及本地提交中的 MID / topic / 源动态字段。
- Chrome 390×844 下浅色、深色、OLED 检查：无水平溢出，表情面板宽 320px 且位于卡片裁切之外，输入表面保持 118px 高。临时视口覆盖已恢复。
- 开发阶段只使用 `pnpm dev`；已核对主脚本与样式产物晚于本次源文件，主脚本包含新的表面类与 @ 分隔逻辑。扩展重载后的实站验收仍待执行。未向 B 站真实发布转发或评论。
