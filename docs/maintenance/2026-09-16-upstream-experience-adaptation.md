## 职责与清理

- 关系仍由原有 `useUserRelations` 写入。只增加活跃消费者、每 MID 请求/写版本与有界缓存，不新增 Store；菜单和 Following 继续使用既有关系变更事件。
- 设置仍由后台 patch 协调器权威对账；canonical → in-flight → queued 顺序、epoch/revision、flush 与恢复保留。删除重复的 ACK render 与设置整对象回写；归一化复用同一函数。
- 首页快照保留既有所有权转移。恢复值从暂存快照移出，剩余字段在恢复钩子后释放；无效 generation 在调用快照 getter 前退出。未删除历史/分页/筛选缓存来换取性能。
- 关注投稿搜索从页面剥离为独立查询职责，普通动态列表/目录写事务仍各有原 owner；不传递整页 refs。分组菜单、事务及成员版本保持原实现。
- 动态评论只新建父链到展示节点的适配，继续使用本地 session/thread/tree guides。折叠状态进入同一快照；评论排序、在途点赞和转发事务保持。
- 截图编码、忙状态与 URL 清理移出按钮挂载器；按钮、快捷键共用。移除原重复编码/下载逻辑和 auth 的外层重复 single-flight 包装。
- 删除仓库内已无引用的旧 `BaseShortcutSetting` / `ShortcutsSettings` 类型；不复活已移除的全局快捷键系统。窗口启用阈值由 `useCardWindow` 统一命名，三处消费者共用。
- 搜索默认词缓存只属于后台该 endpoint，不扩展成通用请求框架。热搜仍属于现有共享搜索 owner。

### 隐私上下文的必要前置

MV3 manifest 使用 `incognito: split`，使网络请求真正使用该普通/无痕上下文的 Cookie，而不只是过滤标签元数据。没有新增主机权限，也没有替用户开启无痕授权。Chrome 明确规定 split 的 Cookie 独立、local/sync 设置存储共享，见[官方说明](https://developer.chrome.com/docs/extensions/reference/manifest/incognito)；共享变更事件参见[固定版本 Chromium 实现](https://chromium.googlesource.com/chromium/src/+/42b022b36244f99067ec9a6aabbcb00d28c7beaf/extensions/browser/api/storage/storage_frontend.cc)。

因此增加仅供四个现有设置消息使用的 `settingsContextRelay`：无痕进程转交原普通进程的设置 patch/读取与云同步入口，不再创建第二个可写协调器或云同步任务。原 epoch/revision、操作 ID、canonical/inFlight/queued 均保留；请求槽有期限、完成清理和后台恢复，不是通用 API 请求框架。TopBar broker 与默认词的会话缓存另按后台上下文分区，防止覆盖对方的缓存记录。
