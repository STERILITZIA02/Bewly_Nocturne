本文描述源码职责，不代表新一次浏览器验收。早期迁移计划及 2026-08-30 模块抽样已归入[历史索引](README.md)。

## 当前契约

- 布局（2026-10-21 左右分区，取代下述 2026-10-20 卡片几何）：左侧视频区约占窗口 50% 宽（右栏不足 360px 时收窄），贴齐窗口上、下与外侧边缘，整个窗口高，直角，无边框，播放器上下留黑边；右栏保留页面内距（底部除外），自上而下为信息模块（最高约 45%，超出时内部滚动）、标签栏（在流内，不再浮动）、面板（滚到窗口底边，从停靠输入框下方穿过）。窄窗口（≤900px）单列：16:9 视频区、右栏。
- 布局（2026-10-20，已被上条取代）：左列为视频卡片与其下的信息模块（标题、作者、操作、简介、标签），右列为评论 / 弹幕 / 推荐；右栏位置设置只交换两列。卡片到窗口顶边、侧边与到标题的距离同为页面内距（行距取页面内距，信息区无顶部内距，标题裁去上方半行距）。信息模块按内容高度排布（超出时内部滚动），卡片至少 16:9 并占满其余高度，播放器上下留黑边。信息模块与右栏不绘制任何容器效果（透明，无边框、圆角、阴影、毛玻璃，简介 / 标签无内嵌底板），保留原内距；右栏以负外边距穿过上下页面内距，评论等面板从窗口顶边滚动到底边，标签栏与输入框浮在原位置，信息流从其下方穿过。窄窗口（≤900px）单列：16:9 卡片、限高信息、右栏。
- 原生播放器留在其所属组件树内，卡片模式按 player frame、铺满模式按整个外壳测量定位，不重建第二个播放器，也不改变地址。
- 铺满窗口：按钮追加在 Bpx 控制栏右侧末尾（原生宽屏 / 网页全屏 / 全屏按钮被隐藏），Esc 返回卡片。切换先把播放器移到终态几何，再从当前绘制帧缩放（中途反向按插值帧续接，画面宽度与中心对齐，竖屏与裁切模式按 `<video>` 实测）：位移缩放为仅 transform 的合成器动画，clip-path 为同时序的主线程动画（2026-10-21 起两端皆为直角，不再插值圆角）。从视频区放大时缩放中的播放器只有画面高，背板 `::before` 按视频区几何（随右栏位置换边）绘制播放器底色补齐上下黑边。期间播放器 `data-bewly-zooming` 与 `#bewly[data-bewly-widescreen-zooming]` 隐藏控制栏、外壳 `data-zooming` 降到播放器之下、跳过玻璃与辅助按钮测量，结束后重测一次。播放器之下的 `.bewly-widescreen-backdrop` 遮住原生页面，卡片时为页面底色、铺满时为播放器底色。
- 性能：模式状态只写在播放器、外壳、背板与 `#bewly` 宿主的属性上，不写 `body` class——该页 body class 变化会重算整页样式（实测 30–40ms/次）。播放器锚定几何变量经 `@property` 注册为不继承，resize 与切换只重算播放器自身。起始帧只改外壳 / 背板属性与面板 opacity；播放器 `data-bewly-display-mode`（控制栏内距与卡片圆角是继承变量，实测约 27ms）与面板 `inert`（约 20ms）由 `heldRestMode` 延到落定帧，那时控制栏仍隐藏。
- 原生重渲染：Bilibili 可能在约 1.2s 时丢弃并重建整个 `.app-v1`（播放器换成新元素）。若外壳已提交，`watchAnchoredPlayerAncestry` 浅观察锚定播放器的祖先链 `childList`，在观察器微任务中调用 `ensureAnchoredPlayer`，新播放器在绘制前回到卡片。
- 作者、工具栏、简介、标签、评论和选集优先保留原节点与事件。需要移动的节点使用占位恢复；原生组件存活由既有桥确认，不能仅凭 DOM 存在或 API 统计判定就绪。
- 评论输入（2026-10-20，后改为固定）：输入框宿主位于 `.bewly-widescreen-panels` 内、评论滚动容器之外，绝对定位于右栏底部内距，评论面板按实测高度预留末尾空间，回弹滚动或列表增减不再使其抖动。最初为评论面板底部 sticky 停靠动态卡片同款输入框（`bewlyWidescreen/commentComposer.ts` 建宿主与 shadow 样式，`PlaybackCommentComposer.vue` Teleport 渲染）。MAIN `inject/externalCommentComposer.ts` 隐藏原生输入框、把楼层 `handleReply` 交给该输入框（原生禁用评论时除外），并把服务端确认的回复写入原生 `newItems`；两侧经 `COMMENT_COMPOSER_TARGET / INSERT` page bridge 通信，只传递经 `toCommentComposerReply` 裁剪的目标字段。
- 侧栏分区分别处理 readiness，迟到或替换的原生根节点由现有观察器接管；缺少必需工具栏时显示既有恢复入口。水合阶段（`resolveWidescreenSidebarHydrationPhase`）：可见时间 12s 内加载；原生评论首屏请求未返回时延长加载态至 30s；之后显示恢复提示并以 1s 节奏继续观察、保持评论预热至 60s，迟到节点到达即清除提示；页面隐藏时暂停并在重新可见时重开预算。
- 视觉收尾（2026-10-20）：卡片带输入框同款 1px 表面边框（2026-10-21 随分区布局移除）；标签栏顶边对齐卡片顶边；操作栏紧凑靠右、与作者按钮行对齐，充电为中性按钮；选集合集框透明且不溢出；播放页隐藏小电视 Logo，停靠控制栏增加“首页”按钮。
- 专业化收尾（2026-10-20）：对齐网格——信息区每行从卡片左缘开始（其滚动层两侧外扩 space-1 容纳悬停与焦点环）；右栏标签栏、面板内容、输入框、原生评论头像（MAIN 将 `#user-avatar` 移到 0，正文与回复缩进为头像 + space-3）、弹幕列表标题与首列共用一条内容线。右栏列表统一为一种行：120px 16:9 缩略图、13/18 两行标题、caption 元信息；行比内容线外扩 space-1，圆角与缩略图同心，悬停只换底色，正在播放为选中底加主题色当前位置圆点（隐藏原生 GIF 与彩色标题）；合集后的推荐在细分隔线下以“接下来播放”分组。在线人数作为状态：卡片模式只把文本镜像到标题下元信息行末（`syncViewerCount`，带 `data-bewly-viewers-mirrored` 时隐藏控制栏胶囊，铺满时恢复），停靠的应用控件从控制栏起始处排列，并以 1px 分隔线与弹幕控件分组。标题 400 字重；作者行为 40px 头像、名字与单行签名、充电 / 关注同行；操作项间距 4px；标签统一为中性 28px 胶囊（话题只留前导图标）。切换标签只淡入；退出铺满的提示标注 Esc。弹幕输入框仍留在原生播放器树内：移到右栏会脱离原生事件归属并破坏铺满模式。
- 右栏标签（2026-10-20）：评论 / 弹幕 / 选集标签栏与首页标签同为轨道滑块（`.bew-segment-control--track`，滑块内缩 2px，hover 只提亮文字）。壳层只维护 `data-active` 并经 `railTabs.ts` 发布标签栏与当前项，`App.vue` 的 `PlaybackRailTabsIndicator.vue` 把共享 `LiquidSegmentIndicator` Teleport 进标签栏；壳层拆除前清空发布，无应用时选中项自绘底板。
- 纯黑模式（2026-10-20）：播放页暂按普通深色显示（`useDark` 在视频播放 URL 上不启用 `oled-dark`），纯黑设计待补充。
- 评论唤醒（2026-10-20）：Bilibili 加载后会整体重渲染评论应用，新 `bili-comments` 可能在折叠线下无限等待懒加载。评论缺失时每次水合经 page bridge（`COMMENT_LIST_WAKE`）由 MAIN 释放其懒加载等待；首屏在 12s 预算后仍转圈时每个预算请求一次原生 `reload()`（应对挂起的请求）。
- 弹幕按用户排序（2026-10-20）：弹幕列表表头在“发送时间”前增加“用户”列（`syncDanmakuSenderOrderButton`），经 `DANMAKU_SENDER_ORDER` 让 MAIN 在原生“发送时间”点击期间替换一次弹幕数组的比较器：按 `uhash` 分组、弹幕多者在前、组内按时间，再点反转；之后点击原生表头照常从升序开始。
- 评论加载（2026-10-20）：评论面板、加载遮罩右栏与原生 `bili-comments-spinner` 统一为单个加载圆环（面板就绪时先闭合再淡出）。
- 信息模块与右栏不再绘制毛玻璃、实色阅读面、边框或圆角裁切，直接位于背板的页面底色上；加载骨架的右栏同样上下贯穿，圆环按整栏高度居中，与面板加载圆环位置一致。
- 底部控制栏复用统一材质设置，原生弹幕发送控件保留权限、校验和事件。液态外壳不通过整体 opacity 创建新的背景采样边界。
- 退出、导航和卸载释放本实例的观察器、定时器、动画帧及监听器，并恢复仍存活的原生节点。

## 加载顺序（2026-10-19 复核）

1. `document_start`：`pageLoadingGuard` 给播放页加一层纯底色遮盖，原生播放器继续在下方初始化。
2. 设置就绪且页面可见：默认进入 Bewly 播放页时挂载加载骨架（与卡片布局及右栏位置一致），同一任务内撤下遮盖，原生页面不出现可见帧。
3. 等待提交：播放器元数据就绪，且原生结构（作者、元数据、弹幕、推荐 / 选集、评论根）齐备时，DOM 解析完成即进入 160ms 稳定窗口后提交；结构仍不完整时才等 `load`（或 DCL 后 3s 兜底）再加 1.2s 沉降后提交。图片、广告等资源不再拖住骨架。
4. 提交后搬入原生节点并开始侧栏水合；原生控制栏、弹幕栏与辅助按钮布局稳定后骨架对齐并淡出，同时执行播放模式的“已应用”后续（默认弹幕、自动播放、稍后再看按钮）。控制栏缺件永远无法稳定时，提交 4s 后照常揭示外壳。
5. 骨架期间原生 `playing`（含自动播放、未交互页面）不会撤下骨架；只有自动连播传入的许可可以让视频提前露出。
