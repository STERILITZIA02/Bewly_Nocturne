# 动态卡片悬浮评论与回复

## 范围与原站依据

用户要求展开动态卡片后，在卡片上回复而不打开新标签页，并确认按原站区分能力：

- 对整条动态“写评论”：表情、@ 用户、图片、同时转发到我的动态。
- 回复根评论或楼中楼：表情、@ 用户；不开放图片与同步转发。

实地检查了 `https://t.bilibili.com/` 的评论与回复编辑器，并只读核对该页实际加载的官方脚本：`https://s1.hdslb.com/bfs/seed/jinkela/commentpc/bili-comments.js`。原站 `showPicBtn` 和 `showSyncToDynamic` 以顶层编辑器命名空间为条件，楼中楼使用不同 namespace。没有替用户发送、上传或转发真实内容。

原站协议：表情业务 `reply`；提及搜索 `/x/v2/reply/at` 返回用户 MID；评论 POST `/x/v2/reply/add` 使用 `oid/type/plat/message/root/parent/at_name_to_mid/pictures/sync_to_dynamic`；同步转发由同一次提交完成，不额外调用创建动态接口。图片使用 `/x/dynamic/feed/draw/upload_bfs`，multipart 为 `file_up`、`biz=new_dyn`、`category=daily` 与 CSRF。原站普通图片控件为 JPG/PNG，最多 9 张、小于 20MB、宽高至少 10px。

## 实现与复用

- `MomentCommentSection.vue` 展开评论即挂载 `MomentReplyComposer.vue`。2026-10-17 改为固定在评论容器底部的常驻输入框，点击回复复用同一实例，仅改变目标。复用既有评论目标解析，不把动态 ID 误用为评论区 OID。新增的本地计数在权威服务端计数更新时归零，避免重复叠加。
- 输入框使用 32px 语义圆角与共享磨砂 / 实色降级，textarea 透明。评论列表按实际编辑器高度预留末尾空间；已在底部时，编辑器变高仍保持最后一条评论露出。空闲编辑器不锁住虚拟列表，草稿、焦点、子面板和写入沿用既有交互保活。
- 只有表情 / @ 面板 Teleport 到卡片外，复用 `useAnchoredPopoverPosition` 的 resize / scroll / visualViewport 生命周期。默认向下，视口不足时向上，按可用高度内部滚动，不受卡片 overflow 裁切；外部点击、Escape、收起及卸载清理面板和监听。
- 表情复用原选择器并按 account + business 隔离缓存；@ 复用已有选择器，新增评论专用数据来源。既支持按钮选择，也支持直接输入 @ 自动补全。只有仍存在于正文的已选择用户名才提交 MID 映射。
- `utils/momentReply.ts` 统一图片限制、返回元数据校验、根 / 父评论关系与表单序列化。大数字 ID 保持字符串；楼中楼沿用原站的回复对象前缀。
- `background/momentReply.ts` 在签名 / 上传前后核对账号及 CSRF；提交使用现有 WBI 密钥工具。公共写入最多发一次，网络或响应不明确时进入“未确认”，保留当前草稿、禁用再次发送，并提供原站检查链接。
- 上传仅在用户提交时发生；选择阶段只做本地校验和预览。回复评论时隐藏顶层图片与转发选项，隐藏附件不会上传；取消回复恢复草稿和附件。已上传成功的图片在明确拒绝后的手动重试中复用；成功 / 卸载释放 object URL。离开卡片或换号后旧上传不能接着发布评论。
- 回复对象只在输入框顶部显示一次，textarea 不重复占位提示。“转发到动态”使用透明背景按钮；常态灰字，hover / 选中只提亮文字，选中勾使用共享 200ms transition 显现，保留勾的位置避免宽度跳动，reduced-motion 仅淡入淡出。
- 评论已发布图片使用撑满正文可用宽度的统一三列网格。三张刚好一行，单 / 双 / 多图的缩略图大小相同；保留原图查看入口。格子间距使用共享 4px token；用户最后确认的铺满三列要求替代早先的半宽方案，删除单图放大、双图两列、窄屏切两列及旧的尺寸 token。
- 服务端确认后的顶层 / 子回复通过现有 normalizer、合并和线程 seed 路径写回当前卡片，并保存到既有账号隔离的内存数据缓存。没有持久化草稿、图片或请求所有者。
- 四种界面语言均已补齐文案，原“在新标签页回复”入口文案移除。
