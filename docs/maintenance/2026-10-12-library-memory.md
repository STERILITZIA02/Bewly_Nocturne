# 资料库页加载与内存优化

用户报告收藏/历史/稍后再看操作迟滞，单页内存曾到 1.3GB。以下区分本轮实际采样与源码判断，不把“图片像素估算”当作进程内存。

## 修复前采样

Chrome 任务管理器读到本任务收藏标签 588–593MB、另一个已有历史标签 730–733MB。没有结束任何浏览器进程，也没有刷新用户自己的历史标签。

同一收藏测试页 DOM：

- 扩展 Shadow DOM 3,754 个元素、90 张图片，无 video 实例。
- 原站被 `display:none` 隐藏的 `#app` 仍有约 8,558 个元素；document 总计 184 张图片，天然尺寸合计 71,536,115 像素。四通道展开约 272.9MiB 是潜在解码体积，不代表这些缓存当时全部驻留。
- 存在隐藏的 `message.bilibili.com/pages/nav/header_sync` 同步 iframe。Manifest 的 all_frames 规则原先仍匹配此地址，而消息页检测也把该地址当作可支持的 iframe。原生同步功能与扩展消息界面是不同职责。
- 未发现 Dark Reader 样式重复注入；Shadow 内两条很小的 element-icons 字体声明来自其他扩展，不修改。

## 已实施

1. **隐藏原版首页图片暂停**：`hiddenHomepageImages.ts` 仅在自定义首页接管并隐藏原版时工作。暂停原版根内 img/picture 的 src/srcset，用单像素替代资源引用；不删除原生 Vue/业务节点，不触碰 `.bili-header`、同步 iframe 或扩展自己的图片。原站后续改图和迟到根也处理，恢复时保留最新原生值；解绑释放所有观察器和引用。
2. **排除纯同步 iframe**：Manifest 与后台目标判定共同排除已观察到的 header_sync 地址；真实消息页、视频页和抽屉入口仍支持，原站同步脚本照常运行。
3. **缩小虚拟窗口**：共享 CardWindow 从前 3/后 4 屏收敛为前 1/后 2 屏，回收保留仅增加半屏；超过 40 项启用虚拟化。焦点、菜单、编辑和操作中的行仍不可回收，保留滚动锚点和反向滚动余量。
4. **收藏夹操作按需挂载**：仅选中行挂载操作区，离场旧行保留到折叠结束再卸载。快速重选取消旧清理，减少闭合目录内的隐藏按钮和组件订阅，不改变最终外观。
5. **首屏补齐有界**：历史、稍后再看、图文收藏一次自动补齐最多 3 页，随后让既有布局/底部哨兵调度；避免首屏布局尚未稳定时用“没有滚动条”把整个列表读完。明确搜索/筛选/排序/批量任务仍允许读取必要的完整元数据。
6. 保留既有预览缓存上限、图片队列和离场媒体清理。修复一个收藏管理 Tooltip 缺失 placement 的开发警告，仍采用原默认的顶部位置。

## 验证

- 新回归覆盖：迟到根与图片、原生 src 更新、恢复原值、保留顶栏、离开后不再处理、同步地址排除、100 行仅一个操作区、首屏分页有界。
- `pnpm lint`、`pnpm typecheck`、`git diff --check` 通过，`pnpm verify:selected-p2` 共 462 项通过。开发 watcher 已更新脚本与 Manifest，未执行独立 build、commit 或 push。
- 同一合成数据回归：500 条稍后再看记录的首屏列表卡片由 15 减至 8；1,200 个关注条目的首屏节点由 41 减至 20。数据条数不减少，焦点/待处理项保留检查继续通过。
- 内存优化前后的实站对比须在新 Manifest 重载后进行。不能用刷新前旧脚本的结果代替新版本，也不从以上组件数量推导“内存必然降低某个百分比”。
- 本轮自动重载未能确认生效；再次刷新同一测试标签仍观察到所有目录都挂载操作区、隐藏原站图片未替换，表明仍是旧版本。已请求用户重载并保留同一测试标签。优化后的实站内存数字暂不记录。
- 现有环境没有可调用的 Chrome DevTools MCP；本轮用 Chrome 任务管理器和 DOM/媒体统计交叉验证，不伪报未测的 INP 或 JS heap 曲线。

## 后续：Tooltip、响应式封面与重复工作

用户提供的日志只有同一类 `Missing required prop: placement` 警告（管理收藏夹／退出管理），附带的大段 Vue runtime 不是另一项异常。收藏调用保留显式顶部定位，公共 Tooltip 现在将 placement 定义为可选且默认 top；包括 Teleport 定位也能取得确定值，未屏蔽 Vue 警告。

- 视频卡片、历史列表和稍后再看两种布局接入 LazyPicture 的 `responsiveCover`。`responsiveImage.ts` 统一提供 160/240/320/480/640/960/1280/1920 宽度候选，浏览器用 `srcset`、实际容器 `sizes` 和 DPR 选图。一个共享 ResizeObserver 管理挂载封面；仅宽度变化更新 sizes，候选 URL 不随宽度重建，无滚动测量/轮询或 ImageBitmap 缓存。候选失败仍回退原 URL。GIF、外站、带查询参数、未知裁切及非 16:9 规则不改写，原图查看入口不降质。
- 收藏元数据分页不再顺带查询所有视频作者头像。VideoCardGrid 仅上报其可见/预加载窗口内需要显示头像的条目；隐藏作者/关闭头像时不发补查。请求按资源去重，切夹及刷新取消旧队列，已完成的有界头像缓存继续复用。旧请求的 finally 不删除同 MID 的新请求。
- `useCardWindow` 对相同键序列复用索引，头像等元数据替换不再重建全部行指标；真实排序、列数、布局变化仍重建，ResizeObserver 仍更新实际行高。
- 图文/合集全量搜索仍保留完整结果语义，但 document 隐藏后不再继续自动翻页，返回再沿当前游标继续；退出释放 visibility listener。
- 审查收藏、历史、稍后再看及共享卡片/图片队列，没有发现这三页自身的高频 setInterval。滚动分页有请求门禁、失败停止和哨兵；TopBar 的共享角标同步、必要的完整搜索/筛选读取不作为错误轮询删除。动画不新增逐帧请求或 DOM 扫描。

验证：全量 selected-p2 469 项通过；最终小幅收尾另跑 memory 专项。完整 lint/typecheck 与 diff 检查通过。真实 Chrome 组件预览在当前屏幕上将 240 CSS px 封面选为 480×270 AVIF，扩为 480 CSS px 后选择 960×540 AVIF；控制台没有 warning/error，light/dark/OLED 切换后图片继续可用。CDN 320×180 候选也验证返回 AVIF。

本次自动重载已成功：同一实站标签观察到隐藏原站图片被暂停。但当前收藏偏好已改为原版 iframe 模式，不能拿它代替 Bewly 页性能验收；临时切回需用户确认，检查后恢复。尚未记录新版本 Bewly 页的实际进程内存，不将单张图片的像素下降等同于整页内存改善比例。

## 2026-10-13：全局资源与依赖审查

### 范围与保留项

- 静态模块扫描覆盖 710 个 TS/Vue/JS 文件、2,237 条显式本地运行时引用，未发现静态引用环；不把类型引用、动态导入和模板自动导入纳入这个结论。
- 检查了定时任务、观察器、请求归属、共享缓存、分页/虚拟窗口、媒体预览、浮层定位和清理路径。现有共享刷新、窗口化、封面尺寸复用和隐藏页暂停继续使用；消息页与稍后再看已确认的外观不变。
- Knip 未报告未使用文件、依赖或无法解析的导入。残留为 5 个接口模型枚举成员（SeasonVersion.Tv、Type.WatchLater、BadgeText 三项），保留协议模型完整性；Knip 因此仍返回非零，不标为全绿。

### 修复

| 共享区域 | 问题 | 处理与验证 |
| --- | --- | --- |
| 用户关系查询 | 旧读取只忽略结果，最后一个使用者离开后仍占用后台请求 | 复用现有可取消读取端口；最后使用者离开时断开，存在其他读者时保留；换号取消旧端口，取消不进入失败冷却，立即重进可新建读取 |
| iframe 图片查看器 | 无关 DOM 变化反复扫描整页；漏掉扩展 Shadow DOM 内打开/关闭 | 将候选收集和状态观察放入 photoViewer 共享模块；只处理相关节点变化，按帧合并测量，跟随 Shadow Root 挂载/移除，卸载取消回调 |
| Tooltip / 浮层 | 滚动事件同步测量，提示文本变长未重新定位；排队任务可能在释放后重新启动 | Tooltip 复用 useAnchoredPopoverPosition；共用滚动合帧、尺寸观察与清理，位置信息用最终布局尺寸避免入场缩放干扰；释放后禁止重新启动 |
| 分集 ID 缓存 | 长期存活文档的 Map 无上限 | 256 项 LRU 内存预算，保持请求合并与命中复用；非法 ID 不发请求。仅缓存 ID 元数据，不缓存媒体或修改服务端记录 |

### 证据与边界

- 同样的 20 批无关 DOM class 变化：旧图片检测路径执行 20 次整页扫描，新路径为 0 次、0 个排队测量帧；原生与 Shadow DOM 内的查看器状态均继续正确通知。
- 同帧 30 次滚动事件仅排队一次定位；文案变宽和缩放动画按最终尺寸对齐，关闭/卸载取消监听与帧任务。
- 81 个关系 ID 的场景中，共享读者离开一个不会中止其他读者；最后读者离开后断开当前端口，剩余两批不发送，取消后立即重试成功。
- Chrome 组件预览中，提示从 70px 扩到 304px 后正确重新定位，保持在视口内；Escape 关闭，控制台无 error。
- 本轮未取得 Chrome DevTools 性能轨迹或同条件进程内存前后对比，上述数字是工作量计数，不是整页 RAM、INP 或 FPS 改善比例。
- 最终验证：`pnpm test` 四组完整通过（659 条 PASS，其中 selected-p2 为 487 项），`pnpm lint`、`pnpm typecheck` 与 `git diff --check` 均退出 0。使用现有开发 watcher 更新产物，未执行 build。
- 用户手动重载开发扩展后，实站 Chrome 验证首页首次加载、刷新后新列表、分区展开与 Escape 关闭、设置通用/外观往返及关闭、首页→动态→首页返回均成功；动态图片查看器能打开、切换下一张并关闭。返回首页后视频链接已恢复，图片查看器节点为 0。本轮所检日志未出现 Bewly 错误；仍有原站 hydration 提示和另一扩展 BTR 脚本启动失败，按来源区分，未修改其他扩展。未执行关注、收藏、消息发送等账号写入，也未将这次当前主题验证扩大为三主题全页面验收。
