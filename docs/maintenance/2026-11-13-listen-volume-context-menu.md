# 听视频音量与原生右键菜单

## 已确认的问题

- 听视频的 UGC 音轨请求未携带 `voice_balance=1`。2026-11-13 对公开样本 `avid=170001&cid=279786&fnval=16&qn=32` 的三次真实接口请求均返回成功，但省略参数或传 `0` 时没有 `volume`，传 `1` 才返回响度数据。该样本 measured 为 −10.2，标准目标为 −14，大动态目标为 −24；原标准模式应应用 −3.8 dB，缺失数据时听视频却使用 0 dB。这是公开接口样本，非用户当前视频的实听测量。
- 只读已渲染的设置菜单或本地存储会漏掉原生播放器当前生效的默认档位；非零手动增益原先只关闭均衡，未将增益应用到听视频。
- 原生右键监听在 `.bpx-player-video-perch`，听视频的 Shadow DOM 舞台是其兄弟节点，右键事件不会到达原生监听器。原菜单层级也低于舞台。

## 实现

- UGC 听视频请求和独立 PGC 音轨入口均请求响度信息；共用预览接口的其他调用方保持原参数。
- MAIN 播放器快照读取当前 `settingStore.getLoudness()` 和 `freeStore.audioAtom.getLocalGain()`，沿用现有页面桥及播放单元校验。菜单/存储作为原生状态不可取得时的既有读取来源。
- 听视频按原生规则计算标准/大动态均衡增益；非零手动增益优先。设置变动由播放器内的交互事件合并触发读取，不增加轮询。
- Web Audio 输出按需创建，第一次播放前设置目标增益，播放中启用时恢复音频上下文；关闭均衡回到单位增益，退出时关闭上下文。保存播放状态直接读取实际音频的音量、静音和倍速，避免等待事件队列时丢失最后一次修改。
- 听视频舞台的右键交回原生视频区域，保留菜单条目、操作、定位和关闭逻辑；仅提升原生菜单层级。Bewly 播放页的菜单表面、文字、边框、阴影、圆角、行高、悬停和禁用态复用现有弹窗与控件 token。
- 原生“精准空降”复制在听视频期间改用实际音频进度，保留原生复制反馈及现有链接净化添加的标题；临时复制监听只覆盖该次菜单操作。

## 验证

- `scripts/verify-selected-p2.mjs`：696 通过、0 失败，包含音轨参数、响应解析、均衡/手动增益、播放中变更、输出上下文释放、音量/静音/倍速状态、原生桥与右键事件回归。
- `pnpm verify:targeted-fixes`、样式失效检查、修改文件 ESLint、`pnpm typecheck` 和 `git diff --check` 通过。
- 独立临时 Chromium 中载入生产样式和真实原生控件模块：93 项自动检查通过，其中本轮新增 6 项覆盖听视频右键打开一次、菜单层级、文字对比、原生操作、点击外部关闭和释放监听。其余为上一轮歌词/控制栏回归。
- 已确认当前 `extension/` 开发产物引用更新后的听视频模块，后台与 MAIN 注入产物包含请求参数及原生音频设置读取。未运行生产 build。

以上为接口实验、源码与自动夹具证据，没有进行用户页面的视觉验收或实际听感比较，也未将原生 EQ 频段滤波和扩展可选的本地 DSP 纳入本轮音频回归。

## 页面复核

重新加载扩展后刷新视频页，在相同音量下依次使用均衡关闭、标准、大动态切换视频/听视频；播放中改音量、静音与增益，再切回视频。听视频舞台上右键打开菜单，确认各选项可用，并在进度变化后复制精准空降链接核对时间。
