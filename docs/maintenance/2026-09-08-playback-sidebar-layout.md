# 播放页侧栏布局调整

在 `message_feature` 上继续修改，保留全部已有未提交工作；没有提交、推送或执行生产 build。

## 行为与实现

- `bewlyWidescreen/styles/layout.ts`：历史弹幕按钮通过定位显示在“弹幕列表 / 三点菜单”同一行右侧，日历改为向下展开并限制在面板可用高度内。按钮、footer、列表父子关系和原生事件均不搬动、不克隆；原生切换到屏蔽等面板时，历史入口仍随原列表隐藏。列表收回原 footer 的高度。
- `bewlyWidescreen/shell.ts`：现有作者槽位和完整操作槽位放入同一自适应 Grid；每列至少 360px，空间不足时自然变成上下两行。五项操作保留各自现有拥有者及原生弹窗路径。
- 简介和标签共用一个圆角容器，保留原有展开、标签 hover、链接和迟到内容更新。容器使用全局 `--bew-surface-inset-bg` 中性黑色叠色，不增加滤镜或边框；没有内容时不显示空壳。OLED 继承深色参数。
- `bewlyWidescreenPolicy.ts` / `storage.ts` / `interactions.ts`：默认宽度为窗口 50%，上限为窗口 85%，移除旧 460px 默认上限与 1920px 拖动上限。原数值设置中 0 表示响应式默认，正数仍为用户保存的像素宽度；不覆盖已有手动宽度。拖动和键盘使用同一约束。
- `loading.ts` / `loadingView.ts` / `styles/loading.ts`：初始化骨架复用相同宽度规则、作者与操作并排阈值、五项操作及简介容器。

## 实际验证

- 完整 `pnpm test` 退出 0。覆盖实际宽度策略在 1440/1920/3840 桌面窗口的默认、最大、已存宽度及实际 shell 的槽位组织、五项事件和标签键盘切换。
- `pnpm lint`、`pnpm typecheck`、`pnpm knip` 退出 0；knip 的既有未使用导出提示不是新增通过项。`git diff --check` 退出 0。
- 现有 `pnpm dev` 持续编译成功，没有直接修改生成产物。
- 浏览器受控夹具导入实际 shell 和实际 SCSS/CSS 模块：1744px 窗口默认 872px；1600px 窗口默认 800px、最大 1360px；360px 侧栏上下回排。实测作者/操作没有水平溢出，历史入口与标题同排，日历位于下方且命中测试可点击。原生结构的列表隐藏/恢复联动、空简介容器隐藏均验证。
- 使用无第三方样式扩展的内置浏览器在 1600×1000 桌面尺寸检查浅色、深色、OLED；简介容器的 backdrop-filter 为 none。Chrome 夹具受到已确认的 Dark Reader 样式注入，因此不以它判断主题颜色。
- 本轮修改前的 Bilibili 页面已确认 MAIN 原生组件挂载探测为 true，投币/收藏弹窗可打开及关闭；未确认投币或更改收藏。该证据不等于新布局验收。
- 本轮新布局尚待用户重载开发扩展后实站复验。Chrome 内部扩展管理页不能由浏览器工具接管；已请求重载，刷新页面确认当时仍未出现新 author-actions 容器。不能以夹具宣称原站日历选择、五项服务端写操作或所有页面模式验收通过。
