# 动态评论展开卡顿修复

## 找到的问题

- 原展开使用 300ms 的 `--bew-ease-emphasized` 过冲曲线，在会推开下方内容的高度动画上产生回弹。
- Chrome 使用 `height: auto` 插值，其他引擎使用 0fr / 1fr 网格。评论加载和常驻输入框测高会在展开过程中改变自然高度，旧实现无法统一控制两条路径的目标变化。
- 每一帧卡片高度都会进入 `useMomentLayout`，更新高度索引并安排虚拟窗口计算、分页检查。已有自然列布局本身就能移动相邻卡片。
- 内层同时做 opacity 淡入，新加入的磨砂编辑器位于这个动画祖先内，形成额外绘制和背景采样边界。

## 修改

`useMeasuredDisclosure` 观察自然内容的尺寸，设置外层显式像素高度；使用现有 200ms 标准曲线，CSS transition 从当前显示值接续新的目标。没有每帧 JS 动画或插值循环，测量由内容 ResizeObserver 和单帧合并触发。内层使用 flow-root，保持自然尺寸；外层只裁切高度，不再加透明度动画。

快速反向切换时保留当前内容，只有真实高度已到终点的 transitionend 才结束；取消、迟到事件、卸载和 reduced-motion 均有对应处理。隐藏页面或取消 transitionend 时使用同一时间 token 的有限兜底；时间解析继续使用 `getMotionDuration`，兼容 `.2s`。

MomentCard 通过 `disclosureMotion` 通知现有布局所有者，并在移动期间通过已有交互保活保留卡片。`useMomentLayout` 跳过动画中间高度的索引提交，在结束时测量并提交最终值一次。普通滚动、宽度变化、评论分页、数据缓存和账号隔离不改。

## 验证

- A11 回归覆盖：数据迟到导致目标变化、关闭 / 重新打开、旧 transitionend 和 transitioncancel、压缩时间单位、reduced-motion、帧和定时器释放。
- 真实布局组合式函数的 3000 条动态 fixture 中，30 个中间高度通知产生 0 次虚拟窗口几何读取，结束后仅 1 次更新；交互卡片保留及最终回收仍通过。
- 定向检查、全量 selected-p2 回归、TypeScript 和修改文件 ESLint 通过。
- 4345 预览使用与生产卡片相同的动画组合式函数、SCSS 和评论组件。模拟评论响应延迟 120ms；Chrome 测到展开 39 个采样帧、收起 25 个采样帧，两个方向的非预期高度反转均为 0，最终展开高度和内容高度均为 541px。快速双击后保持展开，仅有一个输入框。
- 内置浏览器的普通展开 / 收起也未出现高度反转。上述是本地 fixture 的几何 / 生命周期证据，不是实站 FPS 指标。正式扩展仍需重载和刷新后验收。

保持当前评论框、图片布局、页头、侧栏和 Dock 外观；没有执行生产 build 或真实评论 / 图片写入。
